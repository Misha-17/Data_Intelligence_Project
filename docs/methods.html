ARMD construction and evaluation protocol

Status: This is the method and schema appendix. The supplied ARMD source files match the pinned publisher checksums. The real-data results and short report are separate outputs. The instructor extract and exact candidate list were not supplied. The current run uses the stated provisional ARMD panel. No synthetic substitute is used for the main analysis.

1. The prediction task

At the time a culture is ordered, estimate whether a candidate antibiotic will have a susceptible result. Each analytical row is one patient, culture order, organism and candidate antibiotic. The label is 1 for susceptible and 0 for resistant. This is a prediction study, not a treatment recommendation.

Only records with an observed S or R label enter the primary target. An untested candidate has no known label. The pipeline does not create a full nine-drug panel for every culture and does not turn an untested drug into resistant. Organism is needed to define a row and examine subgroups. It is not a predictor because the current organism is usually not known when the culture is ordered.

Eligible rows need a patient key, culture key, organism, parseable shifted order time and a configured candidate. Explicit negative-culture rows are removed. ARMD is described as an adult cohort. As an extra check, an age band with an explicit lower bound below 18 is removed. Missing age is retained and counted; the pipeline does not infer that a person with no age record is an adult. This relies on the source's adult inclusion rule.

The current nine-drug list is provisional: ampicillin, amoxicillin/clavulanate, cefazolin, cefepime, ceftriaxone, ciprofloxacin, gentamicin, piperacillin/tazobactam, trimethoprim/sulfamethoxazole. This is a configurable teaching list. It has not been verified as the standardized STEWARD-AW list. The analysis can be rerun if the instructor supplies a different intended list.

2. Resolve repeated and unclear records

The unique key is patient_id, culture_id, organism, candidate_antibiotic. Text is trimmed and declared null strings become missing. Named drug aliases are mapped to one name. Organism text is lowercased and repeated spaces are removed, without guessing a species.

For each key, matching S labels or matching R labels collapse to one row. If both S and R occur, the whole key is dropped. If any row has an intermediate, unknown, blank, inconclusive, synergy or other invalid label, the whole key is dropped, even when another row says S or R. This conservative rule also drops S plus I. Counts and reasons are written to the label audit.

Order time and culture type must agree within an event. Events with conflicting nonmissing values are removed before candidate filtering. This prevents an arbitrary first row from setting the event metadata. Time values are checked before parsing, so alternate string formats for the same instant can also cause exclusion; the audit makes that loss visible.

3. Select a small common feature set

The eight categorical predictors are candidate antibiotic, age band, anonymous gender code, culture type and four ward flags. The 7 numeric predictors are lab_median_wbc_14d, lab_median_creatinine_14d, vital_median_heart_rate_48h, vital_median_temperature_48h, prior_abx_days_ago, prior_abx_class_count_90d, prior_candidate_resistance_days_ago. These fields use the published ARMD schema and the checked source files. The instructor-source mapping is still pending. They are a proposed shared set, not a verified intersection of several datasets.

Laboratory summaries cover the 14 days before culture order, and vital signs cover the prior 48 hours according to the author manuscript. Exact release times are not supplied. Laboratory and vital units are not fully documented, so values keep their source units and no clinical unit conversion is guessed. Only selected median summaries are retained. Repeated event summaries must agree; conflicting medians become missing instead of being averaged. The feature dictionary gives the exact timing windows and aggregation for each history feature.

Age bands are categories, not exact ages. The meanings of gender codes 0 and 1 are not disclosed, so they stay anonymous. Ward flags can overlap. They do not identify the two hospitals. A missing ward record means unknown setting, not absence from all wards.

Demographics are documented at culture order. Ward flags describe where the culture was collected. The primary design assumes that setting is available at order time. A separate ward recording timestamp is not in the documented core, so this assumption cannot be checked for each row. A future extract should verify it or omit these flags.

4. Prepare supporting tables before joining

Demographics and ward records are first reduced to one row per patient and culture order. Matching nonmissing values collapse. If one feature has several different nonmissing values, only that feature becomes missing. No majority vote is used. Each support table is then left joined to the cohort using both keys, with an explicit many-to-one check.

A left join keeps an eligible culture when a support record is absent. The pipeline checks that joins do not change the number of cohort rows and that the final analytical key is unique. Raw identifiers remain in the analytical file for these checks and patient grouping. The model receives only the named feature list.

5. Split first, then learn from training data

A stable SHA-256 hash samples whole patients using seed 42. The current sampling fraction is 25%. A separate hash gives each patient about 60% chance of training, 20% validation and 20% testing. The realized row and patient fractions can differ. Every culture, organism and candidate for a patient stays in that patient's split.

Fixed label rules, field renaming and key-local agreement checks do not learn population statistics. After those construction steps, the split is assigned before fitting encoders, imputers, scaling, class weights or models. Any categories, averages, medians or class weights learned from data must use training data only. Validation and test rows keep their original class prevalence.

Current susceptibility, current MIC, current resistance summaries, current organism, identifiers and order dates are excluded from model inputs. Current drug panels can reveal outcomes and must not be added as features. Historical drug exposure and prior candidate resistance use a strictly earlier cutoff and the documented day-difference direction. Same-day and future history are excluded. Missing linked history stays missing. Prior candidate resistance is matched to the candidate, so its intended join key also includes that drug.

ARMD applies patient-specific date shifts. These preserve timing within a patient but do not establish real calendar order across patients. A split using shifted dates is not a real prospective time test. Patient splitting limits patient overlap; it does not prove future or outside-hospital performance.

6. Model and evaluation contract

The models are logistic regression and LightGBM, each fitted both with and without balanced class weights. There are also two simple baselines: the overall training susceptible share and the susceptible share for each candidate. An unseen candidate falls back to the overall share. The four learned variants have fixed settings rather than a large hyperparameter search.

The training patients are split again: 80% for base-model fitting and 20% for calibration. This division is patient-disjoint and must contain both labels in each part. Missing categorical values get the explicit category __MISSING__. A one-hot encoder learns categories from base-model fitting rows only; it ignores unseen categories when scoring. Ward zero stays separate from a missing ward value. Numeric fields use medians learned from the fitting subset, missingness flags and scaling fitted only on that subset. Numeric fields entirely absent in fitting receive a fixed placeholder plus an explicit missing indicator; this is not an observed measurement of zero. The source and analytical files keep missing values.

Logistic regression uses L2 regularization with C=1, the lbfgs solver and at most 1,000 iterations. LightGBM uses 220 trees, learning rate 0.04, 15 leaves, at least 50 rows per leaf, L2 regularization 1 and column fraction 0.9. Balanced weights are n / (2 * class_count), computed only on base-model fitting rows. Both baselines use that same fitting subset. Validation, calibration and test rows keep their original class prevalence.

Each learned model has a sigmoid calibration model fitted on the separate 20% training calibration subset. It is an unweighted logistic regression of the label on the logit of the base probability, with C=1000000. Weighted fitting can distort probabilities, so calibrated and raw probability diagnostics are both reported. Validation is not used to fit calibration.

Each model's threshold maximizes balanced accuracy on validation data; ties use the threshold nearest 0.5. The selected learned model has the highest validation antibiotic-macro resistant average precision, with lower Brier score as the tie-break. These choices are frozen before test scoring. Test results for all pre-specified models remain visible, but test performance does not select the winner. Diagnostic calibration slope and intercept fitted on test predictions describe error only; they do not change test predictions.

Let p be the predicted probability of susceptibility and y be the observed label. Resistance scores are 1-p. At a susceptibility threshold t, predict susceptible when p >= t and resistant otherwise. A resistant false negative means a resistant row was predicted susceptible. Report the chosen threshold and how it was set.

  • AUROC: the chance a positive row receives a higher score than a negative row. Report susceptible and resistant views with the correct score direction.
  • AUPRC: average precision. State this numerical definition because trapezoidal precision-recall area differs. Report both classes. Resistant-class average precision uses resistant rows as positive and 1-p as the score.
  • Class-macro metrics: an unweighted average over the susceptible and resistant class. Binary class-macro AUROC equals either properly oriented class AUROC.
  • Drug-macro metrics: an unweighted average of each eligible candidate's metric. Name these separately from class-macro metrics. Report how many drugs were eligible. A candidate with only one observed class has no defined AUROC and must not silently receive zero.
  • Balanced accuracy: the mean of susceptible recall and resistant recall.
  • Resistant precision: the share of predicted resistant rows that are resistant. Resistant recall: the share of resistant rows detected. Precision is set to zero when no row is predicted resistant. Recall is missing when there are no resistant rows.
  • Brier score: the mean of (p-y)^2; lower is better. It tests probability error and depends on class prevalence.
  • Calibration plot: compare mean predicted susceptibility with the observed susceptible share in probability bins. Show a diagonal reference, bin counts and the probability distribution when practical. Sparse bins give uncertain estimates.

Report overall, per-candidate, culture-type, age-band, gender-code, source and shifted five-year-era results, with sample sizes and class counts. Groups below 100 rows or with fewer than 20 rows in either class are flagged as small. Single-class groups have missing AUROC and average precision under this reporting convention. Resistant is not always the minority. Shifted calendar eras are descriptive, not evidence of real calendar change.

Add hospital results only if a real hospital identifier exists. With documented ARMD input, there is one source label and no verified hospital field, so independent dataset or site validation is unavailable. Ward analysis cannot meet that requirement.

Patient-cluster bootstrap intervals respect repeated rows within a patient. Patients are sampled with replacement and all their rows are weighted by their draw count. All models use the same draws, so paired differences use the same sampled patients. The configuration requests 200 replicates. Percentile intervals from a small bootstrap are approximate. Undefined replicate metrics are skipped and usable counts are reported. Models are not refitted in the bootstrap, so these intervals describe test-sample uncertainty for the fitted models, not uncertainty from retraining. Patient clustering does not account for every shared hospital or calendar effect.

7. Profiles and files to inspect

The cohort summary reports rows, patients, culture events, organism-events, shifted time span, label prevalence, candidate depth and duplicate keys, overall and by split. Candidate depth is the number of retained candidate antibiotics for one patient, culture and organism. It counts observed eligible labels, not all drugs that could have been selected.

Missingness is reported for every field overall and by split. Class balance is reported by split and candidate. Construction logs show dropped labels, repeated keys, support conflicts and missing tables. The model package adds model comparison, group results, calibration and uncertainty outputs. Files can be empty or absent when a run is blocked; that is not evidence of perfect data or model performance.

The final schema contract is in final_data_dictionary.csv. The Excel workbook includes the harmonization matrix, dictionary, source-file decisions and target list. The CSV matrix names fields excluded from the core as well as retained fields. Source mappings are documentation, not proof that every source value matches the contract.

9. What the results would and would not show

Only tested drugs with usable S or R results are labeled. Clinicians and laboratories decide what gets tested. This can make the labeled sample different from all patients, all organisms or all possible drug choices. Dropping intermediate and conflicting labels can change prevalence too. A strong test score on observed labels does not establish the same score for untested candidates.

Rows with the same patient, event and organism can occur for several candidates. A random row split would leak shared patient information across sets. The patient split prevents that overlap, while cluster intervals reflect some of the repeated-row dependence. Multi-organism cultures can still produce hard cases because the pre-order inputs cannot distinguish organisms within one event.

The source spans changing laboratory practices and antibiotic use. This scaled model uses a small feature set. It cannot validate causal treatment effects, patient outcomes, present-day breakpoints or performance in another hospital. No comparison between real hospitals is possible without a hospital field. A synthetic run can test code paths but cannot estimate clinical performance or stand in for an approved real-data study.

11. Exploratory follow-up analysis

The advanced appendix and figure gallery extend the original study. They were prepared after the first test results were known. The original fitted model and results stay fixed. A saved protocol fingerprints seven original artifacts. New findings need independent confirmation.

Feature-group comparisons reuse the original model-fitting and calibration patients, model settings and preprocessing rules. Only validation outcomes score these comparisons. The groups are basic fields, basic fields plus laboratory and vital summaries, basic fields plus prior history, all features, and basic fields plus information-availability patterns. The last control replaces observed numeric values with a fixed constant while keeping missing indicators. It does not replace missing clinical values with zero. A known prior-resistance record is itself informative, so this control does not isolate recording practice alone.

Drug-level checks use frozen test predictions and the original cutoff. Probability figures use resistance probability, which equals one minus predicted susceptibility. Overall reliability bins use ten validation quantiles; drug-level bins use five. Duplicate edges collapse, and all bin boundaries are fixed before test evaluation. Bins below 100 rows or 20 resistant results are marked sparse. Brier error, bin agreement and probability distributions are shown together.

Three further cutoffs aim for 70%, 80% and 90% pooled resistant recall on validation. Each keeps ties together and selects the highest resistance cutoff that reaches the target. The exact susceptible-probability rule is stored in JSON, avoiding rounding changes at tied scores. These cutoffs then apply unchanged to test. False alerts and missed resistance are expressed per 1,000 candidate rows, not per patient. A pooled target does not guarantee a target for every drug and is not a clinical treatment rule.

New intervals use 500 shared patient-bootstrap samples. All rows for a sampled patient stay together. Feature-group differences and before/after calibration comparisons use paired draws. Models, cutoffs and bin edges remain fixed during resampling. Intervals are pointwise and omit model-training and selection uncertainty. An interval fixed at zero or one only describes the observed sample. The model-comparison figure keeps the original 200-draw intervals.

The coverage display selects six organisms by their training event frequency. Its denominator is test organism-events with at least one retained S/R result in the panel. Coverage measures retained label availability, not the raw testing rate. An absent label never becomes an outcome. New missingness plots count shared fields once per culture and candidate resistance history once per culture and candidate. The original row-level missingness table remains available.

Run scripts/run_advanced_analysis.py after the primary pipeline. The command builds the extra tables, eight figures, workbook, appendix, updated main report and submission archive. The --presentation-only option reuses saved analysis results. The independent validator recalculates estimates and checks protected hashes before packaging.
